# 背景

## 開発背景
子どもたちのアイデア不足解消の一環として、主に各コースごとにミッションを作成し、そのクリア者を掲示し、学習意欲の向上および創作活動の促進を図る仕組みとして「ミッションボード」の制作を企画した。

本プログラミング教室では、Scratch・LEGO教材・Unity等を活用した制作型学習を採用しており、基本方針として「受講生自身が制作テーマを主体的に考え、開発を行う」自由制作型の授業運営を行っている。この方式は、創造力・論理的思考力・問題解決能力の向上に寄与する教育手法として有効である一方、授業開始時に制作テーマを決定できない受講生が一定数存在するという課題が確認されている。

特に学習初期段階の受講生においては、
・制作可能な作品のイメージが持てない
・自身の技術レベルと作品難易度の関係を把握できていない
・発想経験が不足している
といった要因により、制作テーマ決定までに時間を要し、結果として授業時間の多くをアイデア検討に費やしてしまうケースが発生している。これは学習効率の低下のみならず、達成感や自己効力感の形成にも影響を及ぼす可能性がある。

また一方で、長期間にわたり制作経験を積んできた受講生においても、制作ジャンルや発想の傾向が固定化し、新規性のあるアイデアが生まれにくくなる、いわゆる創作のマンネリ化が課題として見られる。このような状況は、学習の停滞や挑戦意欲の低下につながる可能性があるため、初学者だけでなく経験者に対しても新たな発想機会を提供する仕組みが求められる。

以上の課題を踏まえ、本取り組みでは、難易度別・分野別・習得スキル別に設計された「ミッション」を提示し、受講生が選択式で取り組める環境を整備することで、制作テーマ決定の補助、技術理解の促進、挑戦意欲の喚起を同時に実現することを目的とする。さらに、ミッション達成者を可視化する仕組みを導入することで、適度な競争意識と達成動機を醸成し、教室全体の学習活性化を図る。

以上の背景および目的に基づき、本システムは単なる掲示機能に留まらず、学習支援・動機付け・進捗可視化を統合した教育支援基盤として設計されるものである。

## 解決すべき課題
本システムの導入にあたり、現場運用上解決すべき課題を以下のとおり整理した。

第一に、ミッション情報の可視性不足が挙げられる。実運用を想定した場合、どのようなミッションが存在するのかを一覧的に把握する手段が整備されておらず、受講生および指導者双方にとって選択や判断の基準が不足している。このため、ミッション内容を直感的に把握できる表示環境を整備し、誰でも容易に内容を確認できる仕組みが必要である。

第二に、達成記録の整理および共有手段の不足がある。誰がどのミッションをクリアしたかを記録し可視化する仕組みが存在しない場合、達成体験が個人内で完結しやすく、教室全体での達成感の共有が生まれにくい。したがって、クリア情報を適切に記録し表示できる環境を整備し、達成の実感を共有可能とすることが求められる。

第三に、学習意欲の維持・促進に関する設計上の配慮が必要である。達成状況の可視化はモチベーション向上に寄与する一方、順位表示や比較優位を強調する仕組みは、受講生によっては心理的負担となり、かえって意欲低下を招く可能性がある。本システムではこの点を考慮し、競争順位や優劣比較を目的とした設計は採用せず、あくまで達成の共有と挑戦意欲の喚起に主眼を置いた表示設計とする方針とした。

第四に、指導者の運用負担の軽減が求められる。ミッションの追加・更新・削除を特別な操作や専門知識を必要とする方法で管理する場合、日常業務への負担が増大する。そのため、指導者が日常的に利用しているツール環境を活用し、既存の操作習熟度をそのまま運用に活かせる仕組みを採用することで、管理作業の負担軽減を図る必要がある。

第五に、既存ツールとの安全な連携設計が必要である。教育現場では既にGoogleスプレッドシート等が運用基盤として定着しているため、新規システムが独立した構成となると運用効率の低下を招く可能性がある。一方で、外部アプリケーションからの書き込み処理を許可した場合、外部入力を起点とする不正操作やインジェクション等のセキュリティリスクが想定される。これらを踏まえ、本システムではスプレッドシートとの連携方式をAPIによる読み取り専用構成とし、安全性を確保した上で既存運用資産との統合を実現する設計とした。なお、外部からの入力を伴う機能（例：ミッション依頼フォーム等）については、将来的な拡張候補として位置付け、現段階では実装対象外とする。

以上の課題を踏まえ、本システムは可視化・共有・低負荷運用・安全連携を基本方針として設計されるものとする。

## 対象ユーザー

| ロール | 説明 |
|--------|------|
| 一般（生徒・保護者） | ミッション閲覧 |
| Admin（先生） | ミッション管理・クリア登録 |

Admin は PIN 認証で切り替えられます。認証後は管理パネルが表示され、ミッションの CRUD や依頼レビューが可能になります。アカウント別の認証基盤は将来的な拡張機能として位置づけ、現段階では実装対象外とする。
アカウント認証基盤の導入ができたら、生徒別の達成記録を可視化する仕組みを整備することが可能となる。

## 開発の流れ

当初はモックデータ（`data/seed.ts`）でプロトタイプを作成し、UI や操作感を確認しました。その後、Google スプレッドシートとの API 連携を追加することで、実際の教室環境での運用に対応しました。
